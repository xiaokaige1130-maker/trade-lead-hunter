# 产品级对标与路线图

## 1. 同类开源/产品对标（我们 vs 市场）

| 能力 | Apollo/Hunter 类 SaaS | 开源 Maps/Email Scraper | **本项目 TradeLead Hunter** |
|------|----------------------|-------------------------|------------------------------|
| 多源获客 | 强（付费库） | 通常单一源 | **地图+黄页+B2B+官网+评论+文本** |
| 只要可联系线索 | 默认有联系方式 | 常混无效行 | **默认 require_contact** |
| 业态/联系人画像 | 强 | 弱 | **business_type + 职位推断** |
| 社媒评论截流 | 少 | 少 | **YT/TK/INS/FB（可选）** |
| 自托管 | 否 | 部分 | **Docker + 本地一键** |
| 桌面安装包 | 否 | 少 | **规划 Electron/PyInstaller** |
| 多租户/权限 | 有 | 无 | **规划中（API Token 已具备）** |
| 异步任务队列 | 有 | 少 | **规划 Celery/RQ** |
| CRM 对接 | 有 | 少 | **规划 CSV/Webhook/HubSpot** |
| 反爬与代理池 | 商业 | 自建 | **规划代理与 cookies 池** |

## 2. 当前 v2.0 已具备（产品骨架）

- 统一配置 `config.yaml` + 环境变量（本地/云一致）
- FastAPI 后端 + 专业工具型前端工作台
- Docker / docker-compose 云部署
- 健康检查、版本、功能开关
- 线索库：可联系筛选、业态、联系人、导出 CSV
- 可选 API Token（云上防裸奔）

## 3. 做成「大产品」下一阶段（建议优先级）

### P0 — 马上可卖/可交付
1. **任务中心**：长任务后台跑，进度条、可取消、历史日志  
2. **线索详情抽屉**：一页看全公司/业态/联系方式/来源证据  
3. **批量操作**：多选、改状态、合并去重、打标签  
4. **安装器**：Windows/macOS/Linux 一键包（PyInstaller 或 Electron 套壳）  
5. **备份恢复**：一键导出/导入整个 SQLite

### P1 — 增长与稳定性
6. 代理池 / 轮换 UA / 失败重试  
7. 邮箱 SMTP/MX 深度验证 + 一次性邮箱过滤  
8. Webhook：新线索推送到企业微信/飞书/Slack  
9. 多用户与操作审计（谁导出了什么）  
10. 插件式数据源（实现 `BaseSource` 接口即可挂新源）

### P2 — 平台化
11. 多租户 SaaS  
12. 计费与额度  
13. 浏览器扩展（一键采集当前页）  
14. 与 10 天出海课程内容包联动（模板话术/国家包）

## 4. 架构目标（本地软件 + 云服务双形态）

```
┌─────────────────────────────────────────────┐
│  UI  (工具型工作台 / 未来桌面壳)              │
├─────────────────────────────────────────────┤
│  API  FastAPI  (可 Token)                    │
├──────────────┬──────────────────────────────┤
│  Collectors  │  Lead Core (画像/去重/评分)   │
│  maps/web/…  │  SQLite→可换 Postgres         │
├──────────────┴──────────────────────────────┤
│  data/  可挂载卷 · 可备份 · 可迁移            │
└─────────────────────────────────────────────┘
         ↓ 同一份代码
   本地 start.sh / 桌面安装包 / Docker 云
```

## 5. 设计原则（产品感）

1. **能联上才入库** — 不堆垃圾行  
2. **每条可解释** — 业态、来源、证据链接  
3. **配置即部署** — 不改代码能上云  
4. **工具不是官网** — 密度、侧栏、表格、快捷操作  
5. **合规默认开** — 公开数据、礼貌延迟、可关社媒模块
